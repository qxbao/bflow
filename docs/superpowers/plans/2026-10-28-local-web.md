# Bflow Local Web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use bflow-superpowers:executing-plans to implement this plan task-by-task. If the owner explicitly selects supervised parallel execution, use bflow-superpowers:subagent-driven-development. Steps use checkbox syntax for tracking. This document authorizes planning only; start product implementation on the owner's execution instruction.

**Goal:** Cung cấp web localhost cho người dùng tạo việc, đọc/duyệt gói thiết kế hoặc kết quả, trả lời clarification, resume/cancel và chat tùy chọn trên cùng workflow Bflow.

**Architecture:** Vite UI và HTTP/SSE API cùng origin; CLI inject lifecycle/preview composition vào Local Server. Agentic host sở hữu trusted user interaction facade; form/nút giữ Conversation intake authority nhưng không cần model diễn giải. Herdr cung cấp process/pane/chat transport; Runtime giữ workflow/gates/recovery.

**Tech Stack:** Node >=22.13, pnpm@12.5.1 ở baseline (dùng pin root được integration phê duyệt khi execution), TypeScript, Zod, Vitest, Node HTTP, Vite, React, React Router, Testing Library, Playwright. Chốt phiên bản thực và Node compatibility khi W00; không nâng root toolchain chỉ để cài latest frontend dependency.

**Spec:** [Local Web design](../specs/2026-10-28-local-web-design.md) quyết định scope/behavior; [docs/DESIGN.md](../../DESIGN.md) quyết định visual design/UI conventions. Đọc cả hai trước khi làm UI và áp dụng ui-ux-pro-max-skill ở W06–W08. Không cần prototype hoặc asset export từ công cụ ngoài; design/skill không cấp backend authority.

## Global Constraints

- Web localhost trên máy từng người; nhiều repo trên cùng máy; không cloud/tenant/network bind trong v1.
- Bind 127.0.0.1:4317 mặc định; bootstrap TTL 60 giây, cookie host-only HttpOnly SameSite=Strict, session TTL 12 giờ; CSRF mutation + exact Origin/Host.
- Node >=22.13; pinned pnpm từ root; đọc manifest/scripts trước khi chạy.
- Mọi dữ liệu qua package/process/HTTP boundary parse exported Zod schemas ở @bflow/contracts. Không dùng type assertion thay validation.
- Không thay thế implemented modules hoặc thêm always-success/no-op production adapters.
- Core/Runtime/Conversation/Herdr responsibility và bốn state domains giữ nguyên; Herdr done không là business success.
- Direct actions giữ Conversation-owned intake, host-authenticated web provenance và Runtime guards; không giả physical hook, không cấp trusted ingress cho role tools.
- Shared contracts/root config/lockfile/docs chỉ integrator sửa trong task được giao; leaf agents đề xuất patch/handoff. Public contract cần decision D-WEB-01 có owner thật.
- UI agents phải đọc docs/DESIGN.md và dùng ui-ux-pro-max-skill thực tế được cài khi execution; tìm/đọc SKILL.md theo skill catalog của agent, không giả định đường dẫn hay tự bịa hướng dẫn. Nếu thiếu skill cần thiết hoặc DESIGN.md còn trống, báo rõ phần UI bị thiếu đầu vào; tiếp tục phần backend/functional độc lập, không claim visual compliance. Không tự sửa DESIGN.md để hợp thức hóa UI.
- Source audit 7b158c4 và Herdr 0.9.5 protocol 22 chỉ là baseline khảo sát. Trước mỗi wave kiểm tra approved integration descendant, working tree, worktrees, refs, ancestry/equivalent patches; không reset main hoặc đè uncommitted work.
- Dùng worktree/branch riêng khi implement; không commit dist, playwright output, screenshots test, state, DB, tokens hoặc logs. Không remote push/PR/merge khi chưa được yêu cầu.
- Build trước subprocess/worker tests import dist; affected tests trước, full validation ở integration gates. Không tự tăng độ rộng kiểm thử sau khi đã đủ evidence mà không có lý do.
- TDD required cho trusted ingress/replay/isolation/security; recommended cho DTO mapping/UI; không bắt test-first cho scaffold/CSS. W00 ghi accepted TddDecision/alternative verification.

**Interfaces frozen here (new proposal, not current APIs):**
- @bflow/contracts/web: browser-safe dependency closure, strict exported schemas; no Node/runtime import. Public HTTP version apiVersion: 1; platform envelopes giữ version 3 hiện có.
- WebProject: projectId, displayName, canonicalPath, registrationState; project identity do server canonicalize.
- WebRunView: runId, sessionId, revisionToken, title, originRunId, parentRunId?, continuedAsRunId?, currentRunId, sdlcStatus, coreStatus nullable, transportSummary, tasks, blockers, decisions, availableActions, updatedAt. Lineage derive từ existing delegation metadata/supersededBy; historical parent view giữ nguyên runId, không tráo thành child snapshot. Không ép ba status domains vào một enum.
- WebAction: actionId, kind (create_request/revise_request/answer_clarification/answer_decision/resume/cancel), enabled, disabledReason optional, expectedVersion; approvals trả exact target/revision/generation và safe evidence refs.
- WebCommand discriminated by kind: create_request(title,requestKind,objective,acceptanceCriteria[],constraints[]); revise_request(runId,expectedVersion,objective,acceptanceCriteria[],constraints[]); answer_clarification(runId,questionId,expectedVersion,answer); answer_decision(runId,decisionId,expectedVersion,outcome,reason?,selectedOption?); resume(runId,actionId,expectedVersion); cancel(runId,expectedVersion,reason). Outer fields: commandId UUID, projectId. requestKind dùng enum workflow request hiện có, không trùng discriminator kind. Text limits/spec types của RequirementDraft được reuse/mapped rõ ràng; không invent approved spec.
- WebOperation: operationId=commandId, projectId, owner (host_interaction/local_lifecycle), operationKind, state (accepted/running/applied/failed/reconciliation_required), result?, error?, updatedAt. Typed result có runId/currentRunId/continuedAsRunId khi effect tạo hoặc tiếp tục lineage; không chỉ generic JSON. Stable fingerprint loại bỏ server timestamps; scoped project + local principal + commandId. Local Server index operation owner bền vững trước forwarding, không chuyển owner/kind khi replay.
- WebEvent: apiVersion, cursor(epoch:sequence string), projectId, type (invalidate/operation/notice/chat/reset), resourceIds, occurredAt. No trusted domain success fabricated by event adapter.
- WebChatMessage: messageId, sessionId, runId?, sender(user/conversation), content, createdAt, delivery(accepted/queued/delivered/unknown_delivery/failed), source(web/native). WebChatSend includes messageId, projectId, sessionId, runId?, content.
- WebPage<T>: items, nextCursor?; WebApiError: code,message,retryable,operationId?,correlationId,details safe; registered schema for error/status mapping.
- HTTP mapping: 400 invalid, 401 session, 403 scope/CSRF, 404 missing, 409 stale/conflict, 413 oversized, 422 operation not allowed, 503 unavailable. Valid accepted async command = 202; operation determines final effect.
- POST /api/v1/session/bootstrap {secret}; GET /api/v1/session returns safe session summary/expiresAt/current CSRF under cookie + same-origin read protection and no-store. Reload/tab mới lấy lại CSRF; expired session yêu cầu reopen/pair, không dùng lại consumed bootstrap.
- GET /api/v1/projects; POST /projects {path}; DELETE /projects/:id unregisters only after confirmation and never runs down.
- GET /projects/:id/session, POST /projects/:id/session/start|stop|inspect (inspect means doctor and is read-only), GET /projects/:id/preview.
- GET /projects/:id/runs, GET /projects/:id/runs/:runId, GET /projects/:id/decisions, POST /projects/:id/commands, GET /projects/:id/operations/:operationId.
- GET /projects/:id/artifacts/:artifactId, GET /projects/:id/events, POST /projects/:id/notices/:noticeId/displayed.
- GET /projects/:id/sessions/:sessionId/messages; POST same /messages. Keep chat send separate from structured WebCommand.

Canonical repo context resolver injected by CLI; no browser cwd execution. reconcileSessionOperation quan sát existing lifecycle manifests/receipts/locks và không tự resend mutation. Local Server sở hữu durable lifecycle operation ledger; host readOperation chỉ dùng cho owner host_interaction.
- UserInteractionClient (contracts): listRuns(projectId,query), readRun(projectId,runId), listDecisions(projectId), execute(command), readOperation(projectId,operationId), events(projectId,cursor?), acknowledgeNotice(projectId,noticeId), listMessages(projectId,sessionId,cursor?), sendMessage(input), readArtifact(projectId,artifactId).
