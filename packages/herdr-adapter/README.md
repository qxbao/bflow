# Herdr CLI transport

`createHerdrAdapter({ runner?, binary?, clock?, defaultTimeoutMs? })` implements the current `AgentTransport` port. `HerdrCliTransport.startAgent({ name, kind, paneId, ... })` is an additional startup operation; the pane must already exist. The adapter verifies Herdr CLI 0.9.1 / private protocol 22 / schema 1 during `initialize`. It uses argv-based `spawn` with `shell: false`; a fake `HerdrCommandRunner` can be injected for tests.

Targets must carry a pane ID. The adapter verifies pane, workspace, tab, terminal, agent name and any available `agent_session` before transport operations. A changed occupant is a conflict. Herdr cannot atomically compare an occupant and submit a prompt, so a replacement between preflight and submission can still receive input; a post-submission mismatch is reported as unknown delivery rather than bound to the old execution.

`send` uses `agent prompt` without `--wait`. Success acknowledges terminal writes only. The resulting correlation has `provenance: "orchestrator"` and `verified: false`; it cannot prove a task outcome. Timeout, `agent_prompt_stalled`, lost connection and malformed acknowledgement are `unknown_delivery` with resend forbidden. `reconcile` returns a locally cached acknowledged binding, `not_delivered` for a proven pre-send rejection, or `unknown_delivery`; Herdr 0.9.1 exposes no prompt-specific receipt that can prove non-delivery after an ambiguous submission. Runtime must durably record dispatch intent and receipts and must not blindly resend after restart.

Herdr CLI accepts prompt text as a process argument, so it can be visible to other privileged local processes while the CLI runs. Do not place secrets in `instruction`; the adapter never logs it.

`wait` reports lifecycle state, never business success. `read` returns one bounded terminal snapshot as a `status` message with `data.source: "terminal_snapshot"`, `text`, `target`, `correlationVerified: false`, `executionOutputVerified: false` and `turnIdentity: "unresolved"`. The message's execution ID identifies the caller's observation request, not ownership of the captured terminal text. An incoming handle marked verified does not upgrade terminal snapshot evidence.

Execution-specific wait/read/cancel require both the handle and current pane to expose the same session locator. A different session/occupant conflicts; insufficient evidence returns non-retryable `unknown_delivery` with manual inspection required. Revision changes alone do not establish replacement. `cancel` sends `ctrl+c` only after this check and returns an accepted *request*, never confirmation of stop or proof of prompt-specific cancellation. Herdr cannot atomically compare a session and write keys, so replacement between inspection and the side effect remains possible; post-operation mismatch is uncertain.

Submission and cancellation reserve their idempotency keys before any await. Concurrent identical calls join one operation; conflicting payloads conflict, and uncertain outcomes remain reserved. A proven pre-write failure may be retried with the same payload; its key cannot be reassigned to different content. Duplicate callers may end their own wait without aborting or overwriting the shared operation. Cached outcomes are cloned on storage/return. Deduplication is instance-local; Runtime owns durable cross-restart command state, and this adapter does not claim cross-process exactly-once delivery.

One deadline budget covers all operation substeps. `timeoutMs: 0` is an immediate `timeout/not_started`; negative/non-finite timeouts or invalid deadlines are validation errors. Expiration before a write prevents invocation; expiration/abort after possible write remains uncertain. Startup timeout after possible launch is `unknown_delivery`: inspect the pane/session before retrying, rather than launching again blindly. Runner exceptions stay typed and never expose raw exception text; NUL argv is rejected before spawn.

Run tests with `pnpm exec vitest run packages/herdr-adapter/test/herdr-adapter.test.ts` from the repository root. Live agent/session control is intentionally not part of these unit tests.
