# Hướng dẫn vận hành @bflow/mcp-services

Tài liệu này cung cấp hướng dẫn đầy đủ để vận hành, cấu hình, giám sát và xử lý sự cố cho các host service MCP của Bflow, resource manager và dedicated browser runtime.

---

## 1. Vận hành OS Service của Bflow Shared MCP Gateway

Daemon Bflow Shared MCP Gateway chạy như một service nền cấp người dùng, không đặc quyền. Nó không bao giờ yêu cầu quyền root hay administrator.

### 1.1 Linux (`systemd --user`)

Trên Linux, service unit được cài vào `~/.config/systemd/user/bflow-mcp-gateway.service`.

#### Các lệnh quản lý Service

```bash
# Check service status and MainPID
systemctl --user status bflow-mcp-gateway.service

# Start the Gateway service
systemctl --user start bflow-mcp-gateway.service

# Stop the Gateway service
systemctl --user stop bflow-mcp-gateway.service

# Restart the Gateway service
systemctl --user restart bflow-mcp-gateway.service

# Enable Gateway to start automatically on user login
systemctl --user enable bflow-mcp-gateway.service

# Disable Gateway auto-start on login
systemctl --user disable bflow-mcp-gateway.service

# View live streaming logs
journalctl --user -u bflow-mcp-gateway.service -f

# View recent 100 log lines
journalctl --user -u bflow-mcp-gateway.service -n 100 --no-pager
```

#### Định nghĩa Unit File (`~/.config/systemd/user/bflow-mcp-gateway.service`)

```ini
# Managed by bflow (do not edit; regenerated by bflow os-service-manager)
[Unit]
Description=Bflow Shared MCP Gateway (User Session Service)
Documentation=https://github.com/qxbao/bflow
After=network.target
StartLimitIntervalSec=60
StartLimitBurst=5

[Service]
Type=simple
ExecStart=/usr/bin/env node %h/.local/share/bflow/bin/mcp-gateway-daemon.js --host 127.0.0.1 --port 43110
Restart=on-failure
RestartSec=2
Environment="NODE_ENV=production"
Environment="BFLOW_GATEWAY_HOST=127.0.0.1"
Environment="BFLOW_GATEWAY_PORT=43110"
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=default.target
```

#### Health Check và Repair theo chương trình

```typescript
import { BflowOSServiceManager } from "@bflow/mcp-services";

const manager = new BflowOSServiceManager({ platform: "linux" });

// Probe loopback health
const health = await manager.healthCheck("mcp-gateway");
if (!health.ok || !health.value.healthy) {
  console.warn("Gateway unhealthy, triggering recovery...");
  await manager.recoverIfDead("mcp-gateway");
}

// Full repair (restores canonical unit, reloads systemd, restarts service)
await manager.repair("mcp-gateway", canonicalConfig);
```

### 1.2 macOS (`launchd`)

Trên macOS, service được quản lý như một LaunchAgent trong user session domain (`gui/<uid>`), được cài vào `~/Library/LaunchAgents/dev.bflow.mcp-gateway.plist`.

#### Các lệnh quản lý Service

```bash
# Determine current user GUI domain ID
UID=$(id -u)

# Check service status and PID
launchctl print gui/$UID/dev.bflow.mcp-gateway

# Start / Kickstart the service
launchctl kickstart gui/$UID/dev.bflow.mcp-gateway

# Restart the service (kill and kickstart)
launchctl kickstart -k gui/$UID/dev.bflow.mcp-gateway

# Stop and unload the service
launchctl bootout gui/$UID/dev.bflow.mcp-gateway

# Load and bootstrap the service unit
launchctl bootstrap gui/$UID ~/Library/LaunchAgents/dev.bflow.mcp-gateway.plist

# Enable or disable service
launchctl enable gui/$UID/dev.bflow.mcp-gateway
launchctl disable gui/$UID/dev.bflow.mcp-gateway

# View service stdout / stderr logs
tail -f ~/Library/Logs/bflow/mcp-gateway.out.log
tail -f ~/Library/Logs/bflow/mcp-gateway.err.log
```

### 1.3 Windows (`schtasks` User Logon)

Trên Windows, Gateway chạy qua Windows Task Scheduler trong user interactive session, được lưu dưới thư mục task `\Bflow\` với tên `\Bflow\bflow-mcp-gateway`.

> [!NOTE]
> Việc khởi động trên Windows yêu cầu xác minh tường minh (`windowsVerified: true`). Các thiết lập chưa xác minh thất bại nhanh với `windows_unverified`.

#### Các lệnh quản lý Service

```cmd
:: Query scheduled task status
schtasks /Query /TN "\Bflow\bflow-mcp-gateway" /FO LIST /V

:: Start / Run the task manually
schtasks /Run /TN "\Bflow\bflow-mcp-gateway"

:: End / Terminate the task process
schtasks /End /TN "\Bflow\bflow-mcp-gateway"

:: Enable / Disable task execution on user logon
schtasks /Change /TN "\Bflow\bflow-mcp-gateway" /ENABLE
schtasks /Change /TN "\Bflow\bflow-mcp-gateway" /DISABLE

:: View Gateway log file
type "%LOCALAPPDATA%\bflow\logs\mcp-gateway.log"
```

#### Định nghĩa Task XML (`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\bflow-mcp-gateway.xml`)

## 2. Tinh chỉnh Resource Management

`BackendResourceManager` cân bằng động bộ nhớ, giới hạn tiến trình và các client attachment trên các backend driver.

### 2.1 Cấu hình khởi động Lazy so với Eager

Cấu hình chế độ khởi động backend khi đăng ký service:

```typescript
import { BackendResourceManager } from "@bflow/mcp-services";

const resourceManager = new BackendResourceManager({
  maxProcessCount: 8,
  maxTotalMemoryBytes: 2 * 1024 * 1024 * 1024 // 2 GB
});

// Eager: Lightweight, high-frequency services started on user session init
resourceManager.registerBackend(coreToolsServiceDef, {
  startupMode: "eager"
});

// Lazy: Heavy backends (Chrome DevTools, GitNexus, code search) remain unstarted (0 B RAM)
resourceManager.registerBackend(browserServiceDef, {
  startupMode: "lazy",
  idleTimeoutMs: 30_000,
  maxMemoryBytes: 512 * 1024 * 1024 // 512 MB
});
```

### 2.2 Các tham số tinh chỉnh

| Tham số | Mặc định | Khoảng khuyến nghị | Mô tả |
| --- | --- | --- | --- |
| `maxProcessCount` | `8` | `4` – `16` | Số tiến trình OS backend đồng thời tối đa được phép. |
| `maxTotalMemoryBytes` | `2 GB` | `1 GB` – `8 GB` | Trần bộ nhớ toàn cục trên mọi MCP driver đang hoạt động. |
| `maxMemoryBytes` | `512 MB` | `256 MB` – `1 GB` | Trần bộ nhớ cho mỗi partition driver trước khi bị chấm dứt do OOM. |
| `idleTimeoutMs` | `30000` (30s) | `10000` – `120000` | Khoảng ân hạn trong đó các backend idle vẫn được giữ ấm. |
| `isolateByRepository` | `false` | `true` cho các repo tool có trạng thái | Cô lập các tiến trình backend riêng biệt cho từng Git repository. |

### 2.3 Idle Sweeping định kỳ

Trong production, chạy `sweepIdleBackends()` theo lịch định kỳ (ví dụ mỗi 10–30 giây):

```typescript
setInterval(async () => {
  // Sample memory usage across all running backends
  await resourceManager.sampleMemoryUsage();

  // Terminate backends whose idleTimeoutMs has elapsed
  const swept = await resourceManager.sweepIdleBackends();
  for (const obs of swept) {
    if (obs.status === "stopped") {
      console.log(`Backend ${obs.serviceId} stopped after idle timeout (RAM freed).`);
    }
  }
}, 15_000);
```

### 2.4 Bảo vệ chống chấm dứt sớm

`sweepIdleBackends()` và `release()` sẽ **KHÔNG BAO GIỜ** chấm dứt một backend khi:
1. `activeClientIds.size > 0`: Các agent đang hoạt động vẫn còn attach (`retained_active_clients`).
2. `activeCallCount > 0`: Các lời gọi tool đang in-flight (`retained_active_calls`).
3. `hasUncertainCalls === true`: Một mutation đã xảy ra và đang chờ reconciliation (`retained_for_reconciliation`).
4. `ownership === "external"`: Worker được tiếp nhận từ một external supervisor (`external_retained`).

## 3. Vận hành Dedicated Browser Runtime

`DedicatedBrowserRuntime` quản lý các session Chrome/Chromium cô lập, nằm chặt chẽ ngoài các project repository và được bảo vệ khỏi profile người dùng cá nhân.

### 3.1 Bố cục thư mục chuẩn của OS

Các root profile trình duyệt được tự động phân giải thành:

- **Linux**: `~/.local/share/bflow/browser-profiles/`
- **macOS**: `~/Library/Application Support/bflow/browser-profiles/`
- **Windows**: `%LOCALAPPDATA%\bflow\browser-profiles\`

Mỗi trust boundary nhận một thư mục chuyên dụng có tên:
`<scope-prefix>-<sha256-hash>/user-data/`

Quyền được đặt nghiêm ngặt ở mode `0700` (`rwx------`) trên các filesystem POSIX.

### 3.2 Xử lý sự cố Profile Lock

Chrome dùng khóa đơn tiến trình trên các thư mục profile. `DedicatedBrowserRuntime` duy trì:
1. `.bflow-profile.lock`: metadata JSON với `{ instanceId, pid, debuggingHost, debuggingPort, acquiredAt }`.
2. Các lock gốc của Chrome: `SingletonLock`, `SingletonSocket`, `SingletonCookie`.

#### Phát hiện Profile bị khóa

Khi một tiến trình đang hoạt động khác giữ profile lock:
```
OperationResult.error.code: "conflict"
OperationResult.error.details.diagnosticCode: "profile_locked"
```

#### Giải quyết Lock cũ (Stale Lock)

Nếu Chrome crash hoặc bị kill đột ngột (`kill -9` hoặc mất điện), runtime tự động kiểm tra `isPidAlive(pid)`:
- Nếu PID đã chết, lock cũ và các native lock được tự động unlink ở lần `openPage()` hoặc `reconnectAfterCrash()` tiếp theo.
- Để dọn thủ công một lock cũ:
  ```bash
  rm -f ~/.local/share/bflow/browser-profiles/<profile-dir>/user-data/.bflow-profile.lock
  rm -f ~/.local/share/bflow/browser-profiles/<profile-dir>/user-data/Singleton*
  ```

### 3.3 Phát hiện Crash và kết nối lại

```typescript
import { DedicatedBrowserRuntime } from "@bflow/mcp-services";

const browserRuntime = new DedicatedBrowserRuntime({
  maxReconnectAttempts: 3
});

// Periodic or reactive health check
const health = await browserRuntime.healthCheck(scope);
if (health.value.status === "crashed") {
  console.warn("Detected browser crash. Recovering...");
  const recovered = await browserRuntime.reconnectAfterCrash(scope);
  if (recovered.ok && recovered.value.status === "healthy") {
    console.log("Browser reconnected successfully on 127.0.0.1:", recovered.value.debuggingEndpoint);
  }
}
```

### 3.4 Cô lập đa Agent và quyền sở hữu Page

Khi nhiều agent chạy đồng thời:

```typescript
const agentA: BrowserCallerIdentity = {
  registrationId: "claude-dev",
  runId: "run-001",
  taskId: "task-build",
  scope: repoScope
};

const agentB: BrowserCallerIdentity = {
  registrationId: "codex-tester",
  runId: "run-002",
  taskId: "task-test",
  scope: repoScope
};

// Agent A opens a page
const pageA = await browserRuntime.openPage(agentA, "https://internal.app");

// Agent B attempts to access Agent A's page -> Blocked with page_ownership_conflict
const access = await browserRuntime.getPageContent(agentB, pageA.value.pageId);
// access.error.details.diagnosticCode === "page_ownership_conflict"

// Cookies set in Agent A's browser context are invisible to Agent B
await browserRuntime.setCookies(agentA, pageA.value.pageId, { session: "secret-a" });
```

### 3.5 Dọn dẹp Task tức thì

Khi một agent hoàn tất task, hãy gọi `cleanupTask()` ngay để giải phóng các page và context đang mở mà không phải chờ idle sweep:

```typescript
await browserRuntime.cleanupTask(runId, taskId, scope);
// All task pages closed, browser contexts disposed, dedicated instances shut down.
```
